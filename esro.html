23Explain Hard Real-Time and Soft Real-Time Embedded Systems.M13 marks

Answer

Real-time embedded systems are classified into two types.

1Hard Real-Time Embedded System

In a hard real-time system, the task must be completed within the specified deadline.

If the deadline is missed, the result may become unacceptable or the system may fail to perform its required operation.

2Soft Real-Time Embedded System

In a soft real-time system, the deadline is important, but occasional delay is acceptable.

Even if the deadline is missed, the result may still be useful.

Difference

Hard Real-TimeSoft Real-Time
Deadline must be strictly satisfiedDeadline is less strict
Missing deadline can cause system failureMissing deadline may still allow useful output
Used where timing is criticalUsed where occasional delay is acceptable

38Explain AVR Status Register (SREG).M1Must know🖊️ Diagram7 marks
🖊 LEARN DIAGRAM — SREG

Answer

The AVR Status Register, or SREG, is an 8-bit flag register.

It indicates the conditions produced by arithmetic and logic operations.

The bits of SREG are

I T H S V N Z C

1C — Carry Flag

The Carry flag is set when a carry occurs from the D7 bit.

It is affected by 8-bit addition and subtraction operations.

2Z — Zero Flag

The Zero flag indicates whether the result of an arithmetic or logic operation is zero.

  • Result = 0 → Z = 1
  • Result ≠ 0 → Z = 0

3N — Negative Flag

The Negative flag indicates the sign of an arithmetic result.

If the D7 bit of the result is

  • 0 → positive
  • 1 → negative

4V — Overflow Flag

The Overflow flag is set when the result of a signed operation is too large and causes overflow into the sign bit.

5S — Sign Flag

The Sign flag indicates the sign condition of the result.

6H — Half Carry Flag

The Half Carry flag indicates a carry condition associated with the lower part of an arithmetic operation.

7T — Bit Copy Flag

The T bit is used for bit-copy operations.

8I — Global Interrupt Flag

The I bit controls global interrupt operation.

It is used to enable or disable global interrupts.

Conclusion

SREG is important because it stores the status of arithmetic/logic operations and also contains the global interrupt control bit.

17Packed BCD → ASCIIM2

To convert packed BCD to ASCII

Step 1

Extract lower nibble.

x = mybyte & 0x0F;

Step 2

Add 30H.

x = x | 0x30;

Step 3

Extract upper nibble.

y = mybyte & 0xF0;

Step 4

y = y >> 4;

33Steps of interrupt executionM27 marks
🔥🔥 7 MARK — MEMORIZE THESE 5

The module gives five steps.

Step 1

The microcontroller finishes the instruction currently being executed.

It saves the address of the next instruction, i.e. the Program Counter, onto the stack.

Step 2

It jumps to the fixed location called the Interrupt Vector Table.

The vector table directs it to the ISR address.

Step 3

The microcontroller executes the Interrupt Service Routine.

The ISR continues until the RETI instruction is reached.

Step 4

RETI means Return from Interrupt.

After executing RETI, the microcontroller returns to the point where it was interrupted.

Step 5

The saved PC address is retrieved from the stack and loaded back into the PC.

Normal program execution then continues from that address.

9Round robin schedulingM4★★★★★🖊️ Diagram7 marks

Definition

Round Robin is a preemptive scheduling algorithm in which every process receives a predefined time slot called a time slice.

Working

1The first process in the Ready queue is selected.
2It executes for the predefined time slice.
3If it completes before the time slice ends, the next process is selected.
4If its time slice expires before completion, it is preempted.
5The next process in the Ready queue is selected.
6The process that was preempted is placed back in the queue.
7The process selection continues repeatedly.

Example

Processes

  • P1 = 10 ms
  • P2 = 5 ms
  • P3 = 7 ms

Time slice

3 ms

Initial order

P1 → P2 → P3

The CPU gives each process a maximum of 3 ms per turn.

The important difference from FCFS is

Round Robin adds time-slice-based preemption to the FCFS-like queue order.

For exam preparation, the standard answer is

Definition

A deadlock is a situation in which two or more processes are permanently waiting for resources held by each other, so none of them can proceed.

Necessary conditions

1Mutual Exclusion

A resource can be used by only one process at a time.

2Hold and Wait

A process holds at least one resource while waiting for another resource.

3No Preemption

A resource cannot be forcibly taken away from a process; it must be released by the process itself.

4Circular Wait

A circular chain exists where each process waits for a resource held by the next process.
